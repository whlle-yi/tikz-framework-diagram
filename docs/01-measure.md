# 第 1 步：从位图量取几何

目标：产出一份**像素坐标表**，作为后续所有工作的唯一依据。整个过程不依赖目测。

## 1. 环境

```bash
python -c "import numpy, PIL; print('ok')"   # 缺了就 pip install numpy pillow
```

`scripts/measure.py` 已封装下面所有扫描，直接调用即可：

```bash
python scripts/measure.py hlines img.jpg --x0 300 --x1 920      # 水平线段
python scripts/measure.py vlines img.jpg --y0 200 --y1 460      # 竖直线段
python scripts/measure.py edges  img.jpg --y0 215 --y1 260      # 一排框的左右边界
python scripts/measure.py ink    img.jpg --x0 330 --y0 75 --x1 450 --y1 110   # 文字包围盒
python scripts/measure.py row    img.jpg --y 313 --x0 300 --x1 920            # 单行游程
python scripts/measure.py art    img.jpg --x0 300 --y0 118 --x1 920 --y1 250  # ASCII 结构图
```

## 2. 三类扫描，用途不同

### 2.1 长线段扫描（定骨架）
沿整行/整列找连续暗像素游程，长度超过阈值即视为线。用来找：
- 虚线容器的上下边（整幅宽）
- 每一排方框的上下边（宽度 = 框宽或若干框宽之和）
- 树形支架的横干

阈值建议：`dark < 160~170`，`minlen 60~90`，游程间断容忍 2~3px（抗 JPEG 噪点）。

**虚线要用低阈值单独筛一遍**：虚线覆盖率只有 50~60%，用 0.7 的覆盖率阈值会把整条虚线漏掉——这是最容易犯的漏画原因。见 2.4。

### 2.2 覆盖率扫描（定一排框的左右边界）
给定 y 区间（该排框的内部，避开上下边线和文字），逐列统计暗像素占比。框的左右竖边会在该区间内一直为暗 → 占比接近 1。

```python
sub=(a[y0:y1, x0:x1] < 170); cols=sub.sum(0)/(y1-y0)
xs=[x0+i for i,v in enumerate(cols) if v>0.75]     # 0.75 适合实线框
```
相邻结果聚成一组取均值。得到的 x 序列就是这一排所有框的左右边：
`[313, 427, 434, 548, 554, 668]` → 框1 = 313–427，框2 = 434–548 …

y 区间要选在**文字行之外**（例如框顶 +10 到框底 −10），否则文字笔画会污染结果。

### 2.3 墨迹包围盒（定字号）
取一小块区域，找所有暗像素的外接框，得到文字的宽高：

```python
xs=np.where((a[y0:y1,x0:x1]<150).any(0))[0]   # 宽度
```
用「宽度 ÷ 字数」得到字宽，再换算字号（见 `02-tex-setup.md` 的换算表）。
单个汉字的墨迹高度约为字号的 0.86 倍，宽度约等于字号本身，所以**优先用宽度推算**。

### 2.4 虚线/点线的识别
覆盖率在 **0.30–0.80** 之间的一列/一行，通常是虚线或点线。分两遍扫：
1. 先扫 0.75 以上 → 实线框
2. 再扫 0.30–0.80 → 虚线容器、点线内框

对照实线框的位置排除掉文字行造成的假阳性。典型结果：
`[142(0.58), 281(0.57), 302(0.53), 313(0.52), 908(0.59), 919(0.52), 941(0.58), 1079(0.58)]`
→ 说明这里有 **三组并排的虚线单元**（142–281 / 302–919 / 941–1079），而不是一个大框。

### 2.5 游程打印（定箭头、支架端点）
单行/单列游程能把小构件看得很清楚：

```bash
python scripts/measure.py row img.jpg --y 380 --x0 500 --x1 700
# [(585,587), (623,624)]                     ← 箭头的两条竖直边
# [(566,587), (623,644)]                     ← 箭头头部底边
```
逐行扫一遍箭头区域，就能读出轴宽、头宽、头长、总高。

### 2.6 ASCII 结构图（看懂整体）
把一块区域降采样成字符画，`#` 实、`+` 中、`.` 淡：

```bash
python scripts/measure.py art img.jpg --x0 300 --y0 118 --x1 920 --y1 250 --sx 5 --sy 4
```
用来快速判断「标题→横干→5 条下垂线→5 个框」这类树形结构，比读坐标快得多。
只看结构别看文字（文字会糊）。

## 3. 坐标系统一

全局取**标题框左上角**为 (0,0)，向右为 +x、向下为 +y（TikZ 里再取负）。
所有测量值原样记录，不做任何换算——换算统一放到 TikZ 的坐标系声明里。

## 4. 常见歧义与处理

| 现象 | 原因 | 处理 |
|---|---|---|
| 一排框的左右边界数量是奇数 | 某条边被文字/箭头切断 | 加密扫描区间或换一个 y 区间重扫 |
| 出现两条相距 10px 的平行线 | 相邻两个框各画了一条边（框间有缝） | 按两个框处理，别合并 |
| 折叠卡片出现两组边（如 414 与 456） | 正面 vs 顶面的后边 | 差值即 3D 偏移量 (dx, dy) |
| 一个矩形出现四条边 + 一条斜线 | 竖排标签框的右边被箭头打断 | 见 `03-shapes.md` 的"框与箭头共边" |
| 长线段清单里出现 500~600px 的线 | 可能是横干（树形支架），不是框边 | 结合上下文的短垂直线一起看 |

## 5. 交付物：坐标表

建议直接在生成器里写成数据结构，一眼能核对：

```python
CONTAINERS = [(141,38,1076,366), (141,400,1076,599)]          # 虚线容器
COLS       = [273, 454, 474, 654]                              # 一排框的竖边
ROWS       = [(204,267), (312,389)]                            # 一排行高
LABELS     = [(156,217,52,357,"数据源头归集与预处理")]
```
每加一块就回原图核一遍，别攒到最后。
