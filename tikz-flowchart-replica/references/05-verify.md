# 第 6 步：叠色比对与迭代

这是把"看起来差不多"变成"确实一致"的唯一手段。

## 1. 原理

把原图和渲染结果**按 1:1 叠在同一坐标系**，用颜色区分来源：

```
R = 原图灰度    G = min(原图, 我的)    B = 我的灰度
```
- 只有原图有 → R低 → 显示**蓝**
- 只有我有   → B低 → 显示**红**
- 两者重合   → 三个通道都低 → **黑**

**记住：红=我的，蓝=原图的**。搞反会把"我漏画"看成"我多画"，方向就错了。

## 2. 做出 1:1 渲染

绘图单位 1 unit = 1/72 cm，要让它等于 1 像素：

```
dpi = 72 / 2.54 × 72 ≈ 182.88     → 取 183（误差 0.07%，1300px 上不足 1px）
pixmap = page.get_pixmap(dpi=183)
```

偏移：`standalone` 的 `border=6pt` = 6/72 inch = 15.24 unit。
若绘图左上角在原图 (141,38)，则渲染图的 (0,0) 对应原图 (141−15.24, 38−15.24)。

## 3. 一条命令搞定

```bash
python scripts/overlay.py 素材/1.jpg  out.png \
    --orig 141,38,1076,1417 \      # 原图上要对比的矩形区域
    --border 6 \                    # standalone 的 border(pt)
    --out overlay.png
```

脚本会自动按 `border` 算偏移、裁齐两边、缩放到同尺寸（误差 <1px 时不做缩放）、输出红蓝图。

看结果时：
- **整幅**先看一遍 → 找结构性缺失（整块没画、整条线漏掉）
- **局部放大到 1:1~2:1** → 看箭头、支架端点、竖排文字

## 4. 判读与修复

| 看到的症状 | 结论 | 修法 |
|---|---|---|
| 整块区域只有红/只有蓝 | 元素缺失或多画 | 回到坐标表核对这一块 |
| 一整条横线只有蓝 | 虚线容器漏画（覆盖率阈值设太高） | 用 0.30–0.80 重扫 |
| 竖线与横干差开 10px | 支架端点 x 写错 | 端点必须落在子节点中心线 |
| 框线整体偏 5~10px | 该框的某个边界抄错 | 重扫该排 `edges` |
| 文字红蓝错位 2~5px | 行距或首字位置不对 | 改用逐字/逐行 node，照实测 pitch |
| 文字红蓝错位 10px+ | 字号换算错（当 pt 用了 px） | 见 `02-tex-setup.md` 换算表 |
| 红蓝交替的虚线 | 只是虚线相位不同 | 可忽略 |
| 边缘毛刺、笔画发虚 | 字体渲染差异 | 可忽略 |

## 5. 迭代记录

每轮记一行，别凭记忆：

```
R1  整体骨架对；块3右侧两框整体偏右 8px；块5底部横线端点差 10px
R2  修横线端点；块2 立体卡片标题溢出顶面 → 字号 10.2→9.7
R3  标签竖排改逐字定位；容器顶边 126→120
R4  箭头尺寸统一为 轴26/头55/头长12；末条框 y 1341→1345
```

一般 3–5 轮收敛。**整图至少完整比对 2 轮**才能交付。

## 6. 用户说"不对"时

不要猜、不要重画。按这个顺序：

1. 请他截图或指出大致位置
2. 裁出该区域，原图与我的**上下对照**（同尺寸拼接，不缩放）
3. 仍然看不出就上叠色图
4. 定位到具体参数（哪个坐标、哪个字号、哪个端点）
5. 改生成器 → 重编 → 再叠色确认修好，且没引入新偏差

历史教训：三次"明显不对"分别对应 ①箭头总高小于头长导致只剩个头 ②外围是三个并排虚线单元却画成一个大框 ③标签框末段 `cycle` 斜拉一条线。全是叠色图一眼看出来的，肉眼扫全图反而漏掉。
